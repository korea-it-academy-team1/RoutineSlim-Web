# RoutineSlim — 원본 웹 프론트엔드

이번에 첨부한 `frontend.zip`에서 분리한 **PC 웹용 React 프론트엔드**입니다. 이전에 만든 모바일 앱 형태의 웹과 별개입니다.

원본의 좌측 사이드바, 상단 영역, 넓은 대시보드·구독 표·차트·우측 패널, 색상·글꼴·반응형 배치를 그대로 사용합니다. 대시보드와 나머지 화면의 배치·스타일은 유지했습니다. 요청에 따라 로그인 화면의 가입·소셜 로그인 가용성은 첨부 앱의 실제 구현 상태에 맞췄습니다. 원본과 동일한 파일의 SHA-256은 `docs/PRESERVED-FILES.sha256`에 있습니다.

## 구조와 백엔드 작업 문서

- [기능별 폴더 구조](docs/FRONTEND-STRUCTURE.md)
- [백엔드에서 준비할 작업과 API](docs/BACKEND-TODO.md)

공통 코드는 `src/global`, 기능 코드는 `src/domain`에 모았습니다. 기능 안의 `pages`, `api`, `components`, `hooks`, `utils` 하위 폴더와 `index.js` 중계 파일은 제거했습니다. 회원정보·알림은 `user`, 대시보드·통계·절약은 `stats`로 묶어 `src` 하위 폴더를 53개에서 14개로 줄였습니다.

## localhost:8080으로 확인하기

백엔드 주소는 `http://localhost:8080` 그대로 유지합니다. 최종 웹도 같은 주소로 열려면 프론트의 `dist` 내용을 Spring의 `src/main/resources/static/`에 배치해 **Spring이 화면과 API를 함께 제공**하게 합니다. 정적 파일 허용 설정은 서버에서 확인해야 합니다.

`8080용-빌드.bat`으로 빌드하거나 제공한 정적 배포 ZIP을 사용하세요. [8080 통합 배치 안내](docs/LOCALHOST-8080.md)에 정확한 위치와 실행 방법을 정리했습니다. 프론트 코드를 고치며 보는 개발 미리보기는 5173을 사용하고, 백엔드 8080 주소는 바꾸지 않습니다.

## Windows에서 실행

1. Node.js **24.15.0(팀 기준, 24 LTS)을 일반 설치 프로그램으로 설치**합니다. Node.js ZIP을 풀어 그 안의 npm 폴더로 들어가는 방식은 사용하지 않아도 됩니다.
2. 이 ZIP을 **모두 압축 풀기**로 해제합니다.
3. `package.json`과 `실행.bat`이 보이는 `frontend` 폴더에서 **`실행.bat`을 더블클릭**합니다.
4. 설치가 끝나면 개발 서버가 실행되며 브라우저가 열립니다. 기본 주소는 `http://localhost:5173`입니다. 검은 창은 실행 중 켜두세요.

직접 명령을 실행하려면 같은 폴더에서:

```sh
npm ci
npm run dev
```

이 패키지에는 Java·Maven·Gradle·DB·백엔드 코드가 포함되지 않습니다. 프론트 실행 자체에는 Node만 필요하지만 **로그인과 데이터 기능에는 별도로 실행한 서버가 필요합니다.** 서버 없이 로그인에 성공시키거나 가짜 데이터를 넣지 않았습니다.

## 회원가입 · 소셜 로그인

첨부 앱에는 해당 버튼만 있고 실제 가입/소셜 로그인 절차가 연결되어 있지 않습니다. 웹의 회원가입 버튼과 약관·이메일 인증 가입 화면을 제거했습니다. 앱에 연결되지 않은 아이디·비밀번호 찾기와 계정 복구 화면도 제거했습니다. 소셜 로그인 버튼·안내와 OAuth 조회·시작·오류 요청은 제거했습니다. 일반 아이디/비밀번호 로그인은 유지합니다.

자세한 기준은 [앱과 맞춘 인증 정책](docs/AUTH-PARITY.md)을 확인하세요.

## 서버 주소 설정

`.env.example`을 `.env.local`로 복사하고 백엔드 주소를 바꾼 뒤 개발 서버를 재시작하세요.

```dotenv
API_PROXY_TARGET=http://localhost:8080
VITE_API_MODE=server-dev
VITE_API_BASE_URL=
```

기본값은 `server-dev`입니다. 첨부 서버 규격으로 요청하며 `/api/csrf` 사전 요청을 하지 않습니다. 기존 쿠키 기반 웹 서버를 명시적으로 연결할 때만 `original`을 사용하며, 이 경우 필요한 CSRF 처리를 적용합니다. **첨부한 `RoutineSlim-Server-dev`는 이 원본 웹과 API 규격/기능이 다릅니다.** 서버 전체가 바로 호환되는 상태는 아닙니다.

첨부 서버의 UUID 로그인과 구독 CRUD를 위한 `server-dev` 부분 연결 어댑터도 제공합니다. 사용하는 경우 `.env.server-dev.example`을 `.env.local`로 복사하고 실제 서버 카테고리 ID를 설정하세요. 첨부 서버의 보호 API 인증, 원본 전용 기능 API 등은 서버 측에서 완성이 필요합니다.

[마지막 첨부 서버의 기준 정보](docs/SERVER-BASELINE.md)도 기록했습니다. 기능별 대응과 서버 담당자의 작업 목록은 **[서버 연결 안내](docs/SERVER-INTEGRATION.md)**에서 확인하세요. 없는 서버 API를 성공으로 가장하지 않습니다.

## 빌드·검증

```sh
npm test
npm run build
npm run preview
```

- 변경된 가입·소셜 로그인 정책에 맞춰 테스트를 갱신했으며 전체 88개 테스트가 통과했습니다.
- [화면 비교 및 검증 결과](docs/VALIDATION.md): 대시보드·구독 목록·추가 모달·모바일 화면은 원본을 유지하고, 로그인 화면은 요청한 인증 정책을 적용했습니다.
- 모든 테스트는 모의 API를 사용하는 프론트 검증이며 실제 서버 통합 검증과는 다릅니다.
- 빌드 결과는 `dist/`에 생성됩니다. 백엔드 폴더로 자동 복사하거나 기존 서버 파일을 삭제하지 않습니다.
- 원본이 해시 라우팅(`#subscriptions` 등)을 사용하므로 별도의 React 라우터 서버는 필요하지 않습니다. `index.html`을 더블클릭하지 말고 HTTP 서버로 실행하세요.

기본 시작 화면은 `src/main.jsx`의 React 웹입니다. 예전 가입·소셜 로그인 UI로 우회하지 않도록 사용하지 않는 `public/legacy/` 진입점은 제외했습니다.

## 사용 흐름 보완

- 일부 조회 실패 시 읽힌 대시보드 데이터는 유지하고 확인 불가 집계는 `—`로 표시합니다.
- 조회 오류 후 재시도, 지원되지 않는 기능의 구분, 늦게 도착한 이전 응답 차단을 제공합니다.
- 모달 초기 포커스·Tab 이동·Escape 닫기·이전 위치로 포커스 복귀를 확인했습니다.
- 저장 중 중복 요청을 막고, 실패 시 입력을 유지합니다.
- 화면 렌더링 오류가 생기면 복구 안내를 제공합니다.
- 구독 UUID와 기존 숫자 ID를 결제 내역 연결 시 변형하지 않습니다.

## 코드 이름 · 서식

- API 요청: `apiRequest`, 원화 표시: `formatWon`, 날짜 키: `getTodayDate`
- 서버 변환기: `serverApiAdapter.js`, 공통 통신: `routineSlimApiClient.js`
- 서버가 요구하는 요청/응답 필드명은 그대로 유지합니다.
- `npm run format`으로 서식을 정리하고 `npm run format:check`로 검사합니다.
- 로그인 확인·사용자 구분·UUID 확인·관리자 표시 제한 등 실제 접근 검사는 유지합니다. 현재 서버 모드에 필요 없는 CSRF 요청과 중복 로그인 응답 검사를 정리했습니다.

## 변경 범위

- 백엔드 복사 전용 `build:backend` 명령과 서버 동기화 스크립트 제외
- 개발/미리보기 API 프록시 주소를 `.env.local`에서 설정 가능하도록 분리
- 공통 API 클라이언트에 외부 API 주소 및 선택적 Server-dev 어댑터 연결
- Windows 실행 파일, 연결 문서와 테스트 추가
- `package-lock.json`, 대시보드·공통 스타일·폰트 보존
- 앱의 현재 구현 상태에 맞춰 가입·계정 복구·소셜 로그인 절차와 진입점 제거

현재 제공하는 화면과 기능 코드를 포함합니다. 가입·소셜 로그인은 위의 인증 정책을 따릅니다. 원본 기능을 실제 데이터로 모두 사용하려면 연결할 서버도 같은 API를 제공해야 합니다.
