# 앱과 맞춘 회원가입·소셜 로그인 정책

기준은 마지막으로 첨부된 `RoutineSlim-App-dev.zip`의 실제 코드입니다.

- `LoginScreen.tsx`에는 회원가입 버튼과 네이버·카카오·구글 버튼이 있습니다.
- 실제 로그인 라우트는 `onLogin`만 넘기며 `onSignUp`/`onSocialLogin`을 연결하지 않습니다.
- 별도의 회원가입 화면/라우트도 제공되지 않습니다.

사용자의 "앱에도 없는 절차는 웹에도 없애줘" 요청에 따라 준비 중 버튼도 남기지 않고 다음과 같이 정리했습니다.

| 항목                                      | 웹 동작               |
| ----------------------------------------- | --------------------- |
| 일반 아이디·비밀번호 로그인               | 기존 API 연결 유지    |
| 회원가입 버튼                             | 제거                  |
| 기존 약관·중복 검사·이메일 인증 가입 단계 | 화면/코드 제거        |
| `?register=1` 직접 접속                   | 일반 로그인 화면      |
| 네이버·카카오·구글 로그인                 | 버튼과 관련 안내 제거 |
| OAuth 공급자 조회·로그인 시작·오류 조회   | 요청 제거             |
| 아이디·비밀번호 찾기/계정 복구            | 버튼·화면·라우트 제거 |
| `#recovery` 직접 접속                     | 일반 로그인 화면      |
| 예전 legacy 가입·소셜 화면                | 배포에서 제외         |

서버에 `/auth/signup` 또는 `/auth/social/login`이 있는 것만으로 앱에서 해당 기능이 구현됐다고 간주하지 않습니다. 웹에서 새로운 가입 절차를 임의로 만들거나 로그인에 성공한 것으로 처리하지 않습니다.

향후 앱에 실제 가입 화면·검증 규칙·소셜 인증 절차가 연결되면 그 구현을 기준으로 웹에도 추가할 수 있습니다. 다른 화면·서버 데이터 기능의 연결 조건은 SERVER-INTEGRATION.md에 있습니다.
