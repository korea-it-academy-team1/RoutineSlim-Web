# 백엔드 주소를 바꾸지 않고 localhost:8080으로 웹 열기

백엔드 주소는 `http://localhost:8080` 그대로 유지합니다. 프론트 개발 서버와 Spring 서버가 동시에 같은 주소/포트를 점유할 수는 없습니다.

## 권장: Spring에서 프론트 빌드를 함께 제공

1. 프론트 폴더에서 `8080용-빌드.bat`을 실행하거나 `npm ci` → `npm run build`를 실행합니다.
2. 생성된 **`dist` 폴더 안의 내용**을 실행 중인 Spring 프로젝트의 `src/main/resources/static/`으로 배치합니다. `static/dist/index.html`처럼 한 단계 더 넣지 말고 `static/index.html`, `static/assets/...`, `static/fonts/...`가 되도록 합니다.
3. 기존 정적 파일이 있다면 교체 전에 백업하고, 오래된 번들 파일은 배포 담당자가 확인해 정리하세요. 이 프론트 작업은 백엔드 폴더를 자동 삭제하거나 덮어쓰지 않습니다.
4. Spring 서버를 다시 실행한 다음 **http://localhost:8080**으로 접속합니다. 이 방식에서는 Vite를 실행할 필요가 없습니다.

제공한 `RoutineSlim-Static-8080.zip`을 풀어 `static` 폴더의 내용을 같은 위치에 배치할 수도 있습니다. 이 ZIP은 API 서버를 포함하지 않습니다.

기본 API 주소는 상대 경로이므로 브라우저가 연 Spring 서버의 `/auth`, `/api`로 요청합니다. DB 주소나 백엔드 포트를 바꾸지 않습니다.

## 정적 파일이 차단되는 경우

Spring Security가 `/`, `/index.html`, `/assets/**`, `/fonts/**` 같은 정적 경로까지 인증을 요구하면 로그인 화면을 열 수 없습니다. 서버 담당자가 **정적 리소스 경로만 공개**해야 합니다. 구독·회원 데이터 API의 인증은 계속 적용해야 합니다. 현재 첨부 서버의 인증 연결 문제는 SERVER-INTEGRATION.md에 정리했습니다.

이 작업에서는 서버 보안 코드를 수정하지 않았고, 실제 Spring 환경의 정적 파일 허용 상태도 검증하지 않았습니다. Spring 프로젝트에 파일을 배치할 권한이 없다면 현재 서버 8080에서 웹을 제공하는 작업은 배포 담당자에게 요청해야 합니다.

## 프론트만 개발할 때

`실행.bat`은 프론트를 http://localhost:5173 에서 열고 기존 백엔드 http://localhost:8080 으로 API를 전달합니다. 이는 개발 미리보기 주소만 다른 것이며 백엔드 연결 주소를 변경하지 않습니다.
